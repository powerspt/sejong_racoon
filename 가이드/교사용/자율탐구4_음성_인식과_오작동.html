아무 말에도 움직인다

자율 탐구 — 음성 인식과 오작동 자율 탐구 ④

무엇을 하나

오프라인 한국어 모델로 말을 받아 본다. 자유 발화는 먼저 실패하고, 제한 어휘로 바꾸면 올라간다. 그 까닭을 따진다.

프로젝트에 어떻게

음성 카페 주제에 쓴다. 성공 기준이 "비명령 스무 개에 오작동 0" 처럼 막는 쪽 숫자로 적힌다.

무엇이 필요한가

마이크와 Vosk. 모델은 vosk-model-small-ko-0.22 (풀면 253MB), models/vosk-ko/ 에 둔다. 인식기 코드는 아직 안 만들었다.

어디서 막히나

후보가 여덟 개뿐이면 무슨 소리든 여덟 개 중 하나가 된다. 호출어 · 푸시투토크 · 복창 확인으로 인식기 밖에서 막는다.

docs/voice_control_feasibility.md

교사 노트

장비가 가장 번거로운 탐구입니다. 마이크와 253MB 모델을 미리 받아 두게 하세요.

오작동을 일부러 내 보는 것이 핵심 활동입니다. "점심 뭐 먹지" 로 로봇이 움직이는 것을 본 학생은 방어 설계를 스스로 그립니다.

왜 하나

100분 × 2마이크pip install vosk sounddevice모델 253MB조용한 자리

음성은 완전히 오프라인으로 돌린다. 말소리가 이 노트북 밖으로 나가지 않는다.

인식기는 "모르겠다" 고 말하지 않는다. 후보가 여덟 개뿐이면 무슨 소리든 여덟 개 중 하나가 된다.

그래서 거절하는 일은 인식기가 아니라 우리가 밖에 만들어 둬야 한다.

1자유 발화로 먼저 실패해 본다

모델 폴더(vosk-model-small-ko-0.22)를 코드 옆에 두고 실행한다. 내려받기 87MB, 풀면 253MB 다.

실행하기 전에 몇 개나 맞출지 먼저 적는다.

import queue, json, sounddevice as sd
from vosk import Model, KaldiRecognizer

model = Model("vosk-model-small-ko-0.22")
rec = KaldiRecognizer(model, 16000)   # 음성 → 글자
q = queue.Queue()
def cb(data, frames, t, status): q.put(bytes(data))

with sd.RawInputStream(samplerate=16000, blocksize=8000,
        dtype="int16", channels=1, callback=cb):
    print("말해 보세요 (Ctrl+C 종료)")
    while True:
        if rec.AcceptWaveform(q.get()):
            print(json.loads(rec.Result())["text"])

이렇게 되면 맞다

짧은 단어는 곧잘 맞고, 문장은 엉뚱하게 받아 적힌다.

교실에서 재 보면 아홉 번 중 두 번쯤 맞는다 (2/9).

막히면

마이크를 못 찾는다 — python -c "import sounddevice; print(sounddevice.query_devices())" 로 장치 번호를 확인한다.

모델을 못 찾는다 — 폴더 이름이 vosk-model-small-ko-0.22 인지, 코드와 같은 자리인지 본다.

2쓸 수 있는 말을 여덟 개로 줄인다

고치는 것은 세 번째 인자 하나다. 쓸 수 있는 말을 적어 주는 것뿐이다.

GRAMMAR = json.dumps(["집어","놓아","멈춰","집으로",
                      "왼쪽","오른쪽","앞으로","뒤로"],
                     ensure_ascii=False)

rec = KaldiRecognizer(model, 16000, GRAMMAR)
                                    ↑ 세 번째 인자

이렇게 되면 맞다

같은 사람, 같은 마이크인데 2/9 → 8/9 로 올라간다.

틀리는 하나는 대개 어휘에 없는 활용형 문장이다.

막히면

여전히 낮다면 마이크를 입에 더 가까이, 주변 소음을 줄이고 다시 잰다.

3명령이 아닌 말을 스무 개 넣어 본다

"점심 뭐 먹지", "아 졸려" 같은 말을 스무 개 준비해 그대로 말해 본다.

제한 어휘를 쓰면 정확도는 올라가지만, 무슨 소리든 여덟 개 중 하나로 사영된다.

이렇게 되면 맞다

명령할 생각이 없던 말에 로봇이 움직인다. 이것이 오늘 보려던 장면이다.

막히면

한 번도 안 움직인다면 소리가 작은 것이다. 평소 말하듯 또렷하게 한다.

4인식기 밖에 거절을 만든다

세 가지를 넣고 다시 스무 개를 말해 본다. 무엇이 몇 개를 막았는지 적는다.

# ① 호출어 — "라쿤아" 를 들은 뒤 3초 안의 말만 명령으로 친다
# ② 푸시투토크 — 스페이스를 누르고 있는 동안만 듣는다
# ③ 복창 확인 — "집어 맞습니까?" 에 "응" 이 와야 실행한다

이렇게 되면 맞다

오작동이 눈에 띄게 줄어든다. 대신 쓰기가 번거로워진다 — 그 맞바꿈이 설계다.

막히면

셋 다 넣으면 너무 느리다 — 위험한 명령(집기)에만 복창을 붙이는 식으로 나눈다.

숫자로 재기

두 가지를 따로 센다. 맞히는 힘과 막는 힘은 다른 숫자다.

무엇을횟수결과비고
명령 여덟 개를 차례로10정확 ___ / 10
명령이 아닌 말20오작동 ___ / 20방어 넣기 전
명령이 아닌 말20오작동 ___ / 20방어 넣은 뒤

프로젝트 성공 기준은 보통 아래 두 줄에서 나온다.

프로젝트에 붙이기

음성 카페 주제에 쓴다. 성공 기준이 막는 쪽으로 적힌다 — "10회 중 9회 정확 · 비명령 20개에 오작동 0".

활동지 ④칸 ②줄(인식이 틀리면)에 "기본값은 정지" 를 적고, 복창 확인을 명령표에 넣는다.

인식기 코드(vision/voice_listener.py)는 아직 만들어 두지 않았다 — 위 실습 코드를 팀 파일로 옮겨 쓴다.
