영상 처리 기초

화면은 숫자 배열이다

자율 탐구 — 영상 처리 기초 자율 탐구 ① · detectors.py

무엇을 하나

웹캠 영상을 숫자로 본다. 색을 고르는 숫자 여섯 개(HSV 범위)를 정해 물체를 찾고, 한 줄씩 지우며 코드를 해부한다.

프로젝트에 어떻게

블록 종류를 카메라로 가린다. 위치는 그대로 작업 지도의 칸으로 잡는다 — 카메라로 위치를 재는 것은 그다음 이야기다.

무엇이 필요한가

노트북 웹캠과 OpenCV. 코드는 vision/detectors.py 의 ColorDetector, 색 범위는 vision/config.py 의 COLOR_PRESETS 에 있다.

어디서 막히나

조명이 바뀌면 무너진다. 형광등 아래와 창가에서 같은 숫자가 안 통한다 — 객체 인식(자율 탐구 ②)은 이 문제를 다른 방법으로 푼다.

왜 하나

100분 × 2노트북 웹캠pip install opencv-python색블록 3종흰 종이

주제 1~5 에서 로봇은 어디로 갈지는 알게 됐다. 작업 지도의 칸 번호로 좌표를 잡았다. 그런데 그 칸에 놓인 것이 무엇인지는 아직 모른다.

카메라가 그 "무엇"을 맡는다. 오늘은 가장 단순한 방법부터 — 색으로 가린다.

1그대로 실행해 본다

먼저 돌려 보고, 그다음에 왜 그런지 따진다. 아래를 그대로 적어 실행한다.

import cv2
cap = cv2.VideoCapture(0)      # 화면이 안 나오면 0 -> 1
while True:
    ok, frame = cap.read()
    if not ok: break
    hsv  = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
    mask = cv2.inRange(hsv, (40, 80, 60), (85, 255, 255))
    cv2.imshow("frame", frame)
    cv2.imshow("mask", mask)
    if cv2.waitKey(1) == 27:   # ESC
        break
cap.release()
cv2.destroyAllWindows()

이렇게 되면 맞다

창이 두 개 뜬다. 왼쪽은 보이는 그대로, 오른쪽은 검은 화면에 초록 물체만 하얗게 뜬다.

초록 블록을 움직이면 흰 덩어리도 따라 움직인다.

막히면

검은 창만 뜬다 — VideoCapture(0) 의 0 을 1 로 바꾼다 (노트북 내장/외장 카메라).

ModuleNotFoundError: cv2 — python -m pip install opencv-python 한 번이면 된다.

창이 안 닫힌다 — 창을 클릭해 고른 뒤 ESC. 그래도 안 되면 터미널에서 Ctrl+C.

2숫자 여섯 개를 만져 본다

inRange 의 숫자 여섯 개가 무엇을 잡을지 정한다. 앞 세 개가 아래값, 뒤 세 개가 위값이고 순서는 H(색) · S(진하기) · V(밝기) 다.

H 를 40~85 로 두면 초록이다. 100~130 이면 파랑, 0~10 과 170~180 이면 빨강이다.

한 번에 하나씩만 바꾼다. 바꾸기 전에 어떻게 될지 먼저 적고 실행한다.

mask = cv2.inRange(hsv, (100, 80, 60), (130, 255, 255))   # 파랑
mask = cv2.inRange(hsv, ( 40, 30, 30), ( 85, 255, 255))   # S·V 를 낮추면?

이렇게 되면 맞다

S 의 아래값을 낮추면 연한 색까지 잡혀 흰 덩어리가 커진다.

V 의 아래값을 낮추면 그늘진 부분까지 잡힌다 — 그림자도 같이 잡힌다.

막히면

아무것도 안 잡힌다 — 물체가 화면에 있는지, H 범위가 그 색인지 차례로 본다.

3한 줄씩 지우며 해부한다

코드를 외우지 말고 한 줄씩 지워 본다. 무엇이 사라지는지가 그 줄의 일이다.

# cvtColor 를 지우고 frame 을 그대로 inRange 에 넣으면?
# imshow("mask", ...) 만 남기고 imshow("frame", ...) 을 지우면?
# waitKey(1) 을 지우면?

이렇게 되면 맞다

cvtColor 를 지우면 전혀 엉뚱한 것이 잡힌다 — 같은 숫자라도 BGR 과 HSV 는 다른 뜻이다.

waitKey 를 지우면 창이 아예 안 그려진다 — 그리는 일은 waitKey 가 한다.

4찾은 것의 자리를 숫자로 받는다

흰 덩어리 중 가장 큰 것의 중심을 구하면 화면 좌표가 나온다. 이 네 단계가 vision/detectors.py 의 ColorDetector 가 하는 일 그대로다.

cnts, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
if cnts:
    c = max(cnts, key=cv2.contourArea)
    x, y, w, h = cv2.boundingRect(c)
    print(x + w // 2, y + h // 2)   # 중심 (픽셀)

이렇게 되면 맞다

물체를 오른쪽으로 옮기면 첫 번째 숫자가 커지고, 아래로 내리면 두 번째가 커진다.

막히면

숫자가 미친 듯이 튄다 — 작은 점까지 잡혀서다. cv2.contourArea(c) 가 일정 값보다 작으면 무시하게 한다.

숫자로 재기

인상은 믿을 것이 못 된다. 조건을 두 가지로 바꿔 가며 열 번씩 재고 적는다.

같은 블록을 같은 자리에 놓고, 조명만 바꾼다.

열 번 중 몇 번인지로 적는다. "대체로 잘 된다" 는 기록이 아니다.

프로젝트에 붙이기

프로젝트에서는 종류만 카메라로 가린다. 위치는 그대로 작업 지도의 칸으로 잡는다 — 픽셀을 cm 로 바꾸는 보정은 그다음 이야기다.

쓰는 색은 vision/config.py 의 COLOR_PRESETS 에 이름으로 들어 있다. COLOR_NAME 을 바꾸면 검출기가 찾는 색이 바뀐다.

성공 기준은 이렇게 적는다 — "세 종류를 섞어 열 번 집어 여덟 번 이상 제 칸에 넣는다".

더 가고 싶으면

  • 조명이 바뀌면 무너지는 것을 직접 본 뒤 자율 탐구 ②(객체 인식)로 넘어가면 대비가 선명하다.
  • vision/calibrate_distance.py — 픽셀을 cm 로 바꾸는 보정 (심화)
