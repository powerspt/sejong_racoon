## 2. 실측 1 — 제한 어휘가 모든 것을 바꾼다

Windows 한국어 TTS(Microsoft Heami)로 명령어를 합성해 16kHz 모노 WAV로 만들고, 같은 파일을 두 방식으로 인식시켰다.

- **자유 발화**: `KaldiRecognizer(model, 16000)` — 모델의 전체 어휘 사용
- **제한 어휘**: `KaldiRecognizer(model, 16000, grammar)` — 로봇 명령 12단어만 허용

```python
GRAMMAR = json.dumps(["집어","놓아","멈춰","집으로","왼쪽","오른쪽",
                      "앞으로","뒤로","빨간","파란","초록","블록"], ensure_ascii=False)
rec = KaldiRecognizer(model, 16000, GRAMMAR)
```

| 실제 발화 | 자유 발화 결과 | 제한 어휘 결과 |
| --- | --- | --- |
| 집어 | 집앞 | **집어** |
| 놓아 | 놓았다 | **놓아** |
| 멈춰 | 멈춰 | **멈춰** |
| 집으로 | 집으로 | **집으로** |
| 왼쪽 | 했죠 | **왼쪽** |
| 오른쪽 | 올인 죠 | **오른쪽** |
| 앞으로 | 앞으로 으론 | **앞으로** |
| 뒤로 | 비록 | **뒤로** |
| 빨간 블록을 집어서 왼쪽에 놓아 | 발간 플로그 지반 사 왼쪽 일루 와 | 빨간 블록 집으로 왼쪽 놓아 |
| | **2 / 9** | **8 / 9** |

**단어 단위 명령 8개는 제한 어휘에서 8/8 전부 정확**했다. 실패한 것은 문장 한 개뿐이고, 그것도 어휘에 없던 활용형(`집어서`)이 `집으로`로 끌려간 것이다.

> **설계 결론 1 — 문장을 알아듣게 하지 말고, 단어를 고르게 한다.**
> 로봇 제어에 자연어 이해는 필요 없다. 명령은 유한하고, 유한하면 정확하다.

## 3. 실측 2 — 그런데 이대로 쓰면 위험하다

제한 어휘 인식기에 **명령이 아닌 평범한 교실 대화**를 넣어 보았다.

| 실제로 한 말 | 인식 결과 | 신뢰도 |
| --- | --- | --- |
| 안녕하세요 오늘 날씨가 참 좋네요 | **앞으로 오른쪽 놓아 초록** | **1.00** |
| 수학 숙제 다 했어 | **집으로 집어 멈춰** | 0.72 |
| 선생님 이거 어떻게 해요 | **초록 집어 뒤로 멈춰** | 0.80 |
| 점심 뭐 먹지 | **초록 멈춰 집어** | 0.91 |
| 집에 가고 싶다 | **집으로 집어** | 1.00 |

**5개 전부 명령으로 인식됐다. 거부는 한 번도 없었다.**

이유: 제한 어휘는 **필터가 아니라 강제 사영(projection)**이다. 인식기는 "이 소리가 명령인가?"를 묻지 않고, "허용된 12단어 중 무엇에 가장 가까운가?"만 답한다. 그래서 어떤 소리든 반드시 명령이 나온다.

그리고 **신뢰도는 구조가 없다.** "안녕하세요 오늘 날씨가 참 좋네요"가 신뢰도 **1.00**으로 "앞으로 오른쪽 놓아 초록"이 되었다. 신뢰도 임계값으로는 이 문제를 막을 수 없다.

> **교실에서 이것이 뜻하는 바**: 학생 16명이 떠드는 소리가 전부 로봇 명령이 된다. 로봇팔이 사람을 향해 움직이는 상황(주제 8)에서는 **안전 문제**다.

### 참고 — `[unk]` 토큰은 이 모델에서 안 된다

Vosk 문서는 grammar에 `"[unk]"`를 넣으면 어휘 밖 발화를 `[unk]`로 돌려준다고 안내한다. 그러나 한국어 소형 모델은 어휘에 `[unk]`가 없어 무시된다:

```
WARNING (VoskAPI:UpdateGrammarFst()): Ignoring word missing in vocabulary: '[unk]'
```

따라서 **거부는 인식기 밖에서 만들어야 한다.**

## 4. 설계 — 위험을 없애는 네 겹

제스처 설계(`gesture_control_design.md`)의 "인식 실패의 기본값은 정지"와 같은 원칙이다. 음성은 실패가 더 잦으므로 겹을 더 둔다.

| 겹 | 방법 | 효과 |
| --- | --- | --- |
| **1. 푸시투토크** | 스페이스바를 **누르고 있는 동안만** 마이크를 연다 | 가장 확실. 떠드는 소리가 아예 입력되지 않는다. **1순위 권장** |
| **2. 호출어** | "라쿤아" 뒤 2초 안의 발화만 명령으로 | 손을 안 써도 됨. 단 호출어 자체도 오인식됨 |
| **3. 발화 길이 제한** | 인식 단어 수가 1~2개를 넘으면 버린다 | §3의 오작동 5건은 모두 **3~4단어**였다. 이 규칙 하나로 5건 중 4건이 걸러진다 |
| **4. 복창 확인** | 로봇이 화면·소리로 "집어?"를 되묻고, **제스처 ✊ 또는 버튼으로 승인**해야 실행 | 음성 + 제스처 멀티모달. 느리지만 가장 안전 |

**권장 조합**: 1 + 3 (구현 단순, 효과 큼) → 여유가 있으면 4를 더해 멀티모달로.

이동·집기 같은 큰 동작은 4까지 요구하고, **"멈춰"만은 아무 겹 없이 즉시 실행**한다. 정지는 오작동해도 안전한 쪽이다.

## 6. ⚠️ 실측의 한계 — 반드시 감안할 것

이 수치는 **TTS 합성음** 기준이다. 실제 교실은 다르다.

| 실측 조건 | 실제 교실 |
| --- | --- |
| 단일 합성 화자, 일정한 발음 | 학생 16명, 변성기 음역, 사투리·발음 편차 |
| 배경 잡음 0 | 옆자리 대화, 로봇 모터음, 의자 소리 |
| 마이크 거리 일정 | 노트북 내장 마이크, 거리·각도 제각각 |
| 끊김 없는 단일 발화 | 망설임, 말 끊김, 웃음 |

**실제 정확도는 이보다 낮다.** 8/9를 그대로 기대하면 안 된다. 다만 **자유 발화 대비 제한 어휘가 압도적으로 낫다는 결론**과 **§3의 오작동 구조**는 조건이 바뀌어도 그대로 성립한다(구조적 성질이므로).

→ **수업 전 실제 학생 음성으로 재측정이 필요하다.** 그리고 그 측정 자체가 좋은 학생 활동이다(§7).

## 7. 수업에 넣는다면 — "왜 안 될까?"의 결정판

§3의 결과는 이 과정 전체에서 가장 강력한 교육 소재다. **주제 6의 "AI가 확신한다 ≠ AI가 맞다"와 정확히 같은 교훈이, 이번엔 소리로 반복된다.**

### 활동 설계 (2차시)

| 단계 | 활동 |
| --- | --- |
| 1 | 제한 어휘 인식기로 명령어를 말해 본다 → **잘 된다.** 학생들이 신난다 |
| 2 | **아무 말이나 해 본다** ("점심 뭐 먹지") → 로봇이 움직인다. **교실이 뒤집힌다** |
| 3 | 신뢰도를 화면에 띄운다 → **1.00** → "AI는 자기가 틀린 줄 모른다" |
| 4 | 조별로 **오작동을 막는 방법**을 설계 (§4의 네 겹을 학생이 재발명하게) |
| 5 | 설계한 방법을 코드로 넣고 다시 "점심 뭐 먹지" → 이번엔 안 움직인다 |
| 6 | 토의: 음성 비서(시리·빅스비)는 왜 호출어를 쓸까? |

3번이 핵심이다. 주제 6에서 "신뢰도 0.9짜리 틀린 답"을 찾아오게 했던 활동과 **같은 구조, 다른 감각**이다. 두 번 겪으면 개념이 남는다.

## 8. 커리큘럼 편성안

### 8-A. 중학생 16차시 — **넣지 않는다**

16차시가 이미 빠듯하고(주제 8 프로젝트가 가장 빠듯함), 음성은 제스처와 기능이 겹친다. 확장 4차시가 생긴다면 그때 검토한다.

### 8-B. 중학생 20차시 확장 — **주제 7과 8 사이에 +2차시**

```
주제 7  손을 읽다 (인간-로봇 상호작용)
주제 7.5  목소리를 읽다 — 그리고 AI가 확신할 때   [신규 2차시]
주제 8  프로젝트 (멀티모달: 제스처 + 음성)
```

주제 8에서 "손으로 가리키고, 말로 명령한다"가 가능해진다. Dobot 교과서의 Ch4(Human-Machine Interaction)가 터치·음성을 나란히 두는 구성과 같다.

### 8-C. 고등학생 — **정규 편성 권장** (`curriculum_highschool.md` 참조)

고1이면 §3·§4를 **설계 과제**로 다룰 수 있다. 오작동률을 정량 측정하고(정밀도/재현율), 네 겹 중 어느 조합이 최적인지 실험으로 고른다.

## 9. 구현 계획 (편성이 확정되면)

기존 3층 구조(`gesture_control_design.md`)에 **perception 층의 형제**로 붙인다. intent·action 층은 건드리지 않는다.

```
웹캠  → hand_tracker.py  ─┐
                          ├→ gestures.py → gesture_control.py → arm_helper.py
마이크 → voice_listener.py ─┘   (Command 로 합류)
```

```
vision/
├── voice_listener.py    [신규] Vosk 래퍼. 푸시투토크 + 제한 어휘 + 단어 수 필터
│                               → gestures.Command 와 같은 타입을 발행
├── models/vosk-ko/      [신규] 모델 캐시 (253 MB, git 제외)
└── config.py            [수정] VOICE_* 섹션 추가
```

`config.py` 추가안:

```python
# ───────────────────── 음성 인식 (voice) ─────────────────────
VOICE_ENABLE = False              # 기본 꺼짐. 명시적으로 켠다
VOICE_MODEL_DIR = _os.path.join(_HERE, "models", "vosk-ko")
VOICE_MODEL_URL = "https://alphacephei.com/vosk/models/vosk-model-small-ko-0.22.zip"
VOICE_SAMPLE_RATE = 16000
VOICE_PUSH_TO_TALK = True         # 스페이스바를 누르는 동안만 듣기 (안전 1순위)
VOICE_MAX_WORDS = 2               # 인식 단어가 이보다 많으면 버린다 (오작동 차단)
VOICE_CONFIRM = False             # True 면 제스처/버튼 승인 후 실행
VOICE_GRAMMAR = ["집어", "놓아", "멈춰", "집으로", "왼쪽", "오른쪽", "앞으로", "뒤로"]
VOICE_MAP = {                     # 인식 단어 -> Command.kind
    "집어": "GRIP_CLOSE", "놓아": "GRIP_OPEN", "멈춰": "STOP", "집으로": "HOME",
    "왼쪽": "JOG_L", "오른쪽": "JOG_R", "앞으로": "JOG_F", "뒤로": "JOG_B",
}
VOICE_ALWAYS_ALLOW = ["멈춰"]     # 확인 절차 없이 즉시 실행 (정지는 안전한 쪽)
```

`requirements.txt`: `vosk>=0.3.45`, `sounddevice>=0.5` (sounddevice는 이 PC에 이미 설치됨)

### 단계별 작업

| 단계 | 산출물 | 확인 |
| --- | --- | --- |
| 1 | 모델 자동 다운로드 + `voice_test.py` | 마이크에 말하면 인식 결과가 화면에 뜬다 |
| 2 | 제한 어휘 + 단어 수 필터 | "점심 뭐 먹지" 를 말해도 **명령이 나오지 않는다** |
| 3 | 푸시투토크 | 스페이스바를 안 누르면 아무 반응이 없다 |
| 4 | `Command` 발행 → `--dry-run` | DummyArm 콘솔에 명령이 찍힌다 |
| 5 | 실기 + 실제 학생 음성으로 정확도 재측정 | §6의 한계 해소 |

## 부록. 재현 방법

```bash
pip install vosk sounddevice
# 모델 다운로드 후 압축 해제
curl -LO https://alphacephei.com/vosk/models/vosk-model-small-ko-0.22.zip

python docs/references/stt_probe.py
```

`stt_probe.py` 는 같은 WAV를 자유 발화 / 제한 어휘 두 방식으로 인식해 비교한다.
테스트용 WAV는 Windows 내장 한국어 TTS(Microsoft Heami)로 합성했다 — PowerShell `System.Speech.Synthesis.SpeechSynthesizer`, 16 kHz 모노.
