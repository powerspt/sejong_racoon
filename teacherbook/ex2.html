자율 탐구 — 객체 인식과 모델 평가 자율 탐구 ② · detectors.py

무엇을 하나

배운 적 없는 검출기(YOLO)를 그대로 돌려 본다. 스무 가지를 보여 주고 맞은 것과 틀린 것을 표로 세어 혼동행렬을 만든다.

프로젝트에 어떻게

재활용 분류·품질 검사 주제에 쓴다. 검출기만 바꿔 끼우면 나머지 코드는 그대로다 — make_detector(cfg) 하나로 갈아 끼운다.

무엇이 필요한가

웹캠과 ultralytics. vision/detectors.py 의 YoloDetector, 임계값은 config.py 의 YOLO_CONF = 0.4 다.

어디서 막히나

신뢰도 0.9 로도 틀린다. 임계값을 올리면 틀린 것은 줄지만 못 찾는 것이 는다 — 무엇을 잃을지 고르는 일이 남는다.

공장 시뮬레이션은 extras/04_공장_시뮬레이션.py

교사 노트

영상 처리(①)를 한 뒤에 하면 대비가 선명합니다. 같은 물체, 같은 조명, 검출기만 바꿔 보게 하세요.

혼동행렬은 스무 번만 세어도 충분합니다. 숫자가 작아도 구조는 똑같이 보입니다.

왜 하나

100분 × 2노트북 웹캠pip install ultralytics물건 5종자율 탐구 ① 을 먼저

자율 탐구 ① 의 색 검출기는 우리가 숫자 여섯 개를 가르쳐 줘야 움직였다. 규칙이 보이는 대신, 조명이 바뀌면 무너졌다.

오늘 쓸 것은 규칙을 사람이 적지 않은 검출기다. 대신 왜 그렇게 봤는지 보이지 않는다. 그래서 믿을 만한지 따로 재야 한다 — 그 재는 법이 오늘의 중심이다.

1배운 적 없는 검출기를 돌려 본다

모델 파일은 처음 실행할 때 자동으로 내려받는다.

from ultralytics import YOLO
import cv2
model = YOLO("yolo11n.pt")    # 처음엔 자동 다운로드
cap = cv2.VideoCapture(0)
while True:
    ok, frame = cap.read()
    if not ok: break
    results = model(frame, conf=0.4, verbose=False)
    cv2.imshow("yolo", results[0].plot())
    if cv2.waitKey(1) == 27:   # ESC
        break
cap.release()
cv2.destroyAllWindows()

이렇게 되면 맞다

사람·휴대폰·컵 같은 것에 상자와 이름표가 붙는다. 숫자는 신뢰도다.

색블록에는 아무 이름도 안 붙는다 — 배운 적이 없는 물건이다.

막히면

첫 실행이 느리다 — 모델을 내려받는 중이다. 한 번 받으면 다음부터 빠르다.

설치가 안 된다 — python -m pip install ultralytics. 용량이 크니 인터넷을 확인한다.

2설정 한 줄로 갈아 끼운다

검출기를 바꾸는 데 필요한 것은 설정 한 줄이다. 카메라 코드도, 그리는 코드도 손대지 않는다.

주제 4 에서 RaccoonArm 과 DummyArm 을 같은 이름의 메서드로 맞춘 것과 같은 수법이다.

# vision/config.py
DETECTOR = "color"
        ↓
DETECTOR = "yolo"

# 그리고 그대로 다시 실행
python vision/camera_test.py

이렇게 되면 맞다

같은 창, 같은 조작인데 찾는 방식만 바뀐다.

막히면

바꾸기 전에 같은 조건을 만들어 둔다 — 같은 카메라, 같은 조명, 같은 물건. 그래야 비교한 숫자가 뜻을 갖는다.

3스무 번 세어 혼동행렬을 만든다

물건 다섯 가지를 네 번씩, 모두 스무 번 보여 주고 결과를 적는다. 맞은 것, 다른 이름을 붙인 것, 아예 못 찾은 것 세 가지로 나눈다.

이렇게 되면 맞다

표가 채워지면 "잘 된다"가 아니라 "20번 중 16번" 처럼 말할 수 있게 된다.

막히면

같은 물건인데 들 때마다 결과가 다르다 — 그것도 기록이다. 각도와 거리까지 같이 적어 두면 까닭이 보인다.

4임계값을 올려 무엇을 잃는지 본다

conf 는 "이만큼 확신하지 못하면 아예 말하지 않는다" 는 선이다. vision/config.py 의 YOLO_CONF = 0.4 가 그 값이다.

YOLO_CONF = 0.4   →   0.7 로 올려 본다

이렇게 되면 맞다

틀린 이름표는 줄어든다. 그런데 못 찾는 것이 늘어난다.

어느 쪽이 더 나쁜지는 용도가 정한다 — 불량을 놓치는 것과 양품을 버리는 것 중 무엇이 더 비싼가.

막히면

신뢰도 0.9 인데 틀린 경우를 찾아본다. 숫자가 높다는 것은 후보 안에서 우세하다는 뜻이지 맞다는 뜻이 아니다.

숫자로 재기

스무 번을 세어 아래 표를 채운다. 숫자가 작아도 구조는 똑같이 보인다.

보여 준 것맞게 본 횟수다른 이름을 붙임못 찾음
물건 1
물건 2
물건 3
물건 4
물건 5

합이 20이 되어야 한다. 임계값을 바꾼 뒤 같은 표를 한 번 더 채워 견준다.

프로젝트에 붙이기

재활용 분류·품질 검사 주제에 쓴다. 검출기는 vision/detectors.py 의 make_detector(cfg) 하나로 갈아 끼운다.

성공 기준에 임계값을 같이 적는다 — "conf 0.4 에서 불량 3개 전부 검출, 양품 오검출 2개 이하".

분류 공장 시뮬레이션(extras/04_공장_시뮬레이션_가상.py)에서 검사원만 바꿔 끼워 견줄 수 있다.

더 가고 싶으면

  • 직접 라벨을 붙여 학습시키기 — 사진 수십 장이면 시작할 수 있다.
  • 정밀도와 재현율 — 혼동행렬에서 두 숫자가 어떻게 나오는지.
